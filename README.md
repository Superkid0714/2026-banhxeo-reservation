# 반쎄오갱기데스까 사전예약

첨부된 고객·관리자 화면을 기준으로 구현한 모바일 우선 예약 서비스입니다. Node.js 22.15 이상과 내장 SQLite를 사용하며 외부 패키지 설치 없이 실행합니다. 신규 폴더에서 즉시 확인할 수 있도록 가이드의 권장 Next.js/Spring/PostgreSQL 대신 단일 서버를 선택했습니다.

## 실행

```powershell
Copy-Item .env.example .env
# .env의 관리자 비밀번호와 계좌 정보를 확인하세요.
npm start
```

- 고객: http://127.0.0.1:3000/reserve
- 관리자: http://127.0.0.1:3000/admin/login
- `.env` 없이 실행한 로컬 기본 계정: `admin` / `banhxeo-local-2026`
- `.env.example`을 복사하면 계정: `admin` / `change-this-before-deploying` (변경 필수)
- 예약 데이터를 `data/reservations.sqlite`에 보관합니다. 서버를 재시작해도 유지됩니다.
- 예시 예약 데이터는 자동 생성하지 않습니다. 고객 화면에서 예약을 생성한 뒤 관리자 화면에서 확인하세요.

## 구현

고객 입력 검증, 서버 기준 가격 계산, 날짜별 재고 제한, 예약번호, 계좌 복사, 만료 안내, 예약 링크 저장, 입금 대기 및 확정 화면을 제공합니다. 관리자 로그인·검색·필터·입금 확인·수령코드·문자 이력·재발송·빈 상태를 제공합니다. 목록과 예약 내역은 주기적으로 갱신됩니다.

SQLite `BEGIN IMMEDIATE` 트랜잭션으로 재고와 예약·입금 확정·문자 작업 생성의 원자성을 보장합니다. 중복 확정 시 409를 반환하며, 6자리 코드는 암호학적 난수와 UNIQUE 제약으로 보호합니다. 문자 실패는 결제 상태를 되돌리지 않습니다. 미입금 예약은 기본 60분 후 만료되어 재고를 반환합니다. 입금 확인 전에 실제 은행 입금 내역을 직접 비교해야 합니다.

공개 예약 조회 경로의 `[code]`는 추측 가능한 예약번호 대신 48자리 비밀 토큰입니다. 고객의 예약 링크를 아는 사람이 예약 정보를 볼 수 있으므로 공유하지 마세요. 관리자 API는 HttpOnly 세션 쿠키, 8시간 만료, 로그인 시도 제한, 같은 출처 검사를 적용합니다.

## 문자 연결

기본 `SMS_MODE=mock`에서는 발송 성공 상태를 시뮬레이션하며 실제 문자를 보내지 않습니다. UI에도 개발 모드를 표시합니다. `SMS_MODE=mock-fail`은 3번 실패 후 FAILED 상태가 되어 재발송 화면을 검증할 수 있습니다.

실제 연결은 `SMS_MODE=webhook`, `SMS_WEBHOOK_URL`, `SMS_API_KEY`를 설정합니다. 어댑터에 다음 POST 요청을 전송합니다.

```json
{"phone":"01012345678","message":"확정 안내 내용","idempotencyKey":"sms-1"}
```

어댑터는 실제 SMS/LMS 업체 API에 연결하고 발신번호·LMS 길이를 처리해야 합니다. HTTP 2xx와 `{"success":true}`를 반환하면 SENT로 처리합니다. 업체에 접수한 상태를 의미하며 단말 수신을 보장하지 않습니다. 어댑터는 idempotencyKey 기준 중복 발송 방지를 구현해야 합니다. 10초 타임아웃, 최대 3번 시도 후 FAILED로 처리합니다. 수동 재발송은 새 작업 이력을 만듭니다. 비밀키는 프런트엔드에 전달하지 않습니다.

## 검증

```powershell
npm run check
npm test
```

통합 테스트는 인증, 입력 검증, 가격 조작 방지, 동시 재고 초과, 중복 입금 확인, 공개 링크 보안, 만료 재고 반환, 문자 실패·재발송을 검사합니다.

## 실제 운영 전에 확정할 항목

계좌·예금주, 날짜별 예약 한도, 환불 상세 기준, 담당자 연락처, 개인정보 보유기간 및 삭제 절차, 문자 업체·발신번호·어댑터를 확정해야 합니다. 현재 동의 안내는 검토용 문구이며 개인정보 자동 삭제는 구현하지 않았습니다. HTTPS 배포와 `NODE_ENV=production`을 사용하세요. 운영 모드는 기본 비밀번호·16자 미만 비밀번호·개발용 SMS 설정을 거부합니다. 외부 접속은 HOST를 설정해야 합니다.

현재 구조는 단일 서버·SQLite 운영에 맞춰져 있습니다. 여러 서버를 함께 실행하려면 PostgreSQL, 공유 인증 저장소와 작업 선점 구조로 전환해야 합니다. DESIGN.md는 제공되지 않아 첨부 이미지와 Figma의 공통 디자인 가이드를 기준으로 사용했습니다. 음식 사진은 첨부한 사전예약 화면의 상품 사진 영역을 표시합니다.
